它压的是什么

PNG 的体积主要浪费在颜色量化上：一张图里实际用到的颜色远少于格式允许的颜色数。TinyPNG 把这部分冗余去掉，再用一套算法把损失控制在肉眼难以察觉的范围。

JPEG 的处理思路不同，重点在压缩曲线和色度采样。两类格式的处理逻辑分开，效果都比较稳定。

结果是：体积常能降到原来的一半以下，画质在正常观看距离下基本看不出差别。但它是不可逆的，反复压缩会累积损失。

网页与 App 场景怎么用

  1. 先备份原图。压缩不可逆，设计源文件单独存档。
  2. 按用途定尺寸。先把图裁到实际展示尺寸，再压缩。一张 3000px 宽的图压到 200KB，和裁到 1200px 再压，效果差很多。
  3. 批量拖入。网页版支持多选，压缩完打包下载，文件名会自动加后缀便于区分。
  4. 检查透明通道。PNG 的透明背景会保留，但半透明边缘可能出现轻微色带，按钮、图标类素材要放大看一眼。
  5. 上线后测加载。压缩只是第一步，配合 CDN 和合适的缓存策略才算完成。

开发者的接入方式

提供 API，按压缩次数计费，返回压缩后的文件和节省比例。适合接进 CMS 的上传流程，让编辑不用手动处理。

常见做法是：上传时先调接口压缩，再把结果写入对象存储。注意设置超时和失败回退，别让压缩环节卡住整个上传。

也有现成的插件，WordPress、Figma 等生态里都能找到，装完自动处理，适合不想写代码的人。

免费额度与限制

网页版单次可上传的文件数量和单文件体积有上限，超出的部分需要分批，或使用付费套餐。

免费额度按压缩次数计算，每月重置。个人博客、少量商品图基本够用；电商站每天上新几十张图，很快就会触顶。

付费套餐提升单次数量和 API 调用量，团队协作还能共享额度。

什么时候不该用它

  • 需要无损压缩。印刷、摄影归档这类场景，改用无损工具或直接保留原图。
  • 需要极致小体积。WebP、AVIF 在同等画质下更小，先转格式再谈压缩。
  • 动图。GIF 不在处理范围内，动图需要专门的优化工具。
  • 已压过多次的图。重复压缩只会变糊，找不到原图就到此为止。

TinyPNG 常见问题

TinyPNG 免费吗？

有免费额度，按月计算压缩次数，单次文件数量有限制。高频使用或接 API 需要付费。

压缩后画质会变差吗？

会有不可逆的细节损失，但正常观看距离下通常看不出来。需要印刷或存档的图，保留原件。

支持 WebP 吗？

支持，WebP 的压缩效果通常比 PNG、JPEG 更明显，适合网页素材。

能批量压缩吗？

网页版支持多选批量，但单次数量有限；大批量建议用 API 或桌面插件接入流程。

透明背景会丢吗？

PNG 的透明通道会保留。半透明边缘可能出现轻微色带，图标类素材建议放大检查一遍。
